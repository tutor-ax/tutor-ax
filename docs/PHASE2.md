# 2단계 — 관리자·학습 화면 공개 데모

## 범위

원본 저장소와 운영 데이터는 변경하지 않았다. 1단계의 안내 화면을 실제 React 조작 화면으로 교체했다. 합성 데이터 기반 프런트엔드이며 **운영 서비스 전체와의 기능·디자인 완전 동등성을 주장하지 않는다.**

관리자와 학생 성적 fixture는 독립적이다. 관리자의 점수 편집이 학생 성적 화면에 반영되는 종단 간 연동은 아직 없다. 공개 관리자는 실제 인증/권한이 없고 각 방문자의 브라우저 저장소에만 쓰므로 실제 개인정보를 입력하면 안 된다.

## 접속·브랜딩

- 성적·단어·지문: `/tutor-ax/`에서 데모 진입 후 탭 이동.
- 관리자: `/tutor-ax/admin` 또는 `/tutor-ax/admin/`. Pages가 디렉터리 끝 `/`로 정규화할 수 있다. hash 없이 새로고침 가능.
- 기존 `#/admin.html` 및 `/admin.html` 진입도 유지.
- 빌드 시 `dist/admin/index.html`을 실제 생성하므로 SPA 404 우회가 아닌 정적 진입점이다.
- 사용자가 제공한 `standard_logo.svg` 원본을 `src/assets/academy-logo.svg`로 포함. 공통 헤더 흰 배경에 원래 색상을 유지하며 공개 배포 요청 범위로 사용한다.

## 구현

관리자:
- 반·학생 추가/수정/삭제, 반별 주차 추가/선택.
- 동적 점수 항목·만점·커트라인, 빈 점수와 0 구분, 원점수를 바꾸지 않는 재시험 통과.
- 별도 모의고사 추가/선택·점수·동적 항목·미응시·메모.
- 주차별 출석·과제 수행률·평가 및 미인증 대상 표시.
- 작성자/작성시각이 있는 조교 메모, 삭제 확인.
- 클리닉 메모·요일·시간 편집과 명시적 시간별 그룹 표시.
- 문자는 합성 대상의 통합 미리보기만 제공. 발송 기능 없음.
- 로컬 자동 저장, 명시적 스냅샷 저장/복원 및 초기화. 손상 데이터 발견 시 기존 내용을 덮어쓰지 않고 알림.
- 반 이동은 학생·주차가 없는 새 반으로만 지원하고 기존 원본 성적은 보존. 이미 데이터가 있는 반으로의 날짜/주차 매칭 이동은 지원하지 않음.

단어:
- 직접 작성한 데모 어휘 8개, 두 DAY 중 복수 범위 선택.
- 플래시카드·뜻 표시·즐겨찾기.
- 뜻/영단어 쓰기 및 선택 퀴즈·중복 제출 차단·결과·재시도.
- 오답노트와 원본의 2회 연속 정답 시 자동 제외 규칙.
- 브라우저별 저장 및 명시적 초기화 확인. 다른 앱의 저장소는 보존.
- 원본 `그룹|DAY|단어` 형식의 단어 ID 유지.

지문:
- 원본의 실제 학습 흐름(그룹 → 지문 → 문장 해석)을 기준으로 구현.
- 직접 작성한 두 영어 지문만 제공. 원본 교재/DB 지문은 가져오지 않음.
- 문장별 해석 토글, 전체 해석·단어 목록, 이전/다음·지문 목록.
- URL의 `g`, `p`를 유지해 같은 지문 새로고침 복원.
- 원본에는 지문 퀴즈 채점이 없으므로 임의의 AI 평가 기능을 추가하지 않음.

## 의도적으로 미이전/상이한 점

- 단어 한국어 품사/어간/유사도 판정, Gemini 판정, 개인/공유 인정 답안·교사 요청은 미이전. 현재는 데모 정답 일치 비교이며 화면에서 이를 고지한다.
- 단어 문제 순서와 선택지는 재현 가능한 고정 방식이며 원본의 무작위 20문항 추출과 다르다.
- 반 간 기존 성적 매칭 이동, 모든 문자 종류별 대상·서식·발송 정책, 클리닉 자연어 파싱·학년별 집계, 서버 필드별 자동 감사 이력은 미이전.
- 관리자 데모 항목·만점은 합성 설정이다. 실제 시험 설정이나 성적의 재현이 아니다.
- 원본 CSS에서 가져온 학습 스타일은 각 React 영역으로 범위를 제한했다. 관리자에는 기존 색상·카드·탭 구조를 적용했다. 관리자/학습의 원본 픽셀 동등성은 검증하지 않았으며, 성적 화면의 원본 데이터·크기 비교는 계속 수행한다.

## 검증

- 기존 테스트와 관리자 CRUD/추적/반 이동/복원·학습/URL/로고 회귀 테스트.
- 390px·1440px 브라우저에서 관리자 점수/재시험/새로고침/모의고사와 학습 카드/오답/즐겨찾기/지문 복원 확인.
- Pages asset base로 별도 빌드 후 동일 관리자·학습 테스트 실행.
- 기존 CSP `connect-src 'none'` 유지. 브라우저 업무 동작 중 fetch/XHR 요청이 없는지 확인.
- Pages 배포 workflow가 Pages 빌드 브라우저 테스트 통과 후에만 artifact를 업로드·배포하도록 강화.

`docs/VERIFICATION.md`는 1단계 당시 기록이다. 이번 검증은 `npm run check`, `npm run test:pages`로 재실행하며 최신 CI 결과를 기준으로 확인한다.
