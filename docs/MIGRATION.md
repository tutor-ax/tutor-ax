# 1단계 마이그레이션 기록

## 상태와 범위

학생/학부모 성적 확인 프런트엔드를 React로 옮긴 **합성 데이터 기반 개발본**이다. 운영 로그인과 데이터 연결은 구현하지 않았다. 따라서 실제 고객 서비스의 이전 완료나 운영 배포 완료를 뜻하지 않는다.

관리자·단어 공부·지문 공부는 이후 단계이며 현재는 명확한 안내 화면만 제공한다. 기존 고객 저장소에 쓰기·커밋·배포를 하지 않았다.

## 기준 소스

- score-system: https://github.com/jongchankim-cloud/score-system
- 기준 커밋: `12cf096681ef78724ccb58c451e7929000e0f97f`
- 이전 대상: `index.html`, `theme.css`
- 참고: `supabase/functions/parent-login/index.ts` (응답 계약 확인용; 운영 함수와의 일치 미검증)
- 후속 단어/지문 대상: https://github.com/jongchankim-cloud/vocab-study
- 후속 검토 기준 커밋: `b04cb0d56b355906064f3f4a316d822d31d62c47`

원본 저작권/이용 권한은 유지되며 이 작업본을 공개 OSS로 재허가하지 않는다. 원본 고객 대화, 비밀번호, 연락처, 실제 학생 데이터, API 키는 복사하지 않았다. 코드의 학원 표기와 디자인은 요청에 따라 유지했다.

## 이전한 동작

- 성적 확인의 기존 헤더·탭·520px 최대 너비·카드·입력칸·색상·반응형 CSS.
- 주차와 모의고사를 합친 최신 날짜순 선택 목록. 연말/연초 정렬과 최신 주차 기본 선택 유지.
- 고정/추가 채점 항목 설정, JSON 추가 점수, `null`·`undefined`·0 구분 및 레거시 총점 fallback.
- 재시험 통과 시 원래 점수 보존. 미통과와 통과 배지 구분.
- 결석 안내와 보충 점수 동시 표시, 과제 없음 숨김, 수행률 미기재 구분, 클리닉 메모 줄바꿈.
- 모의고사 미응시 표시 및 비대상 시험 숨김, 비교 그룹 기반 평균·석차.
- 기존 원점수 기반 누적 평균/최고 점수 및 주차 순서의 Chart.js 추이. 시험 난이도·만점을 정규화하는 새 지표로 바꾸지 않음.
- 새로고침·탭 이동·뒤로 가기 및 직접 경로 접근. 이는 로컬 데모 상태이며 원래 서버 인증 동작을 검증한 것은 아님.

## 의도적인 차이

1. 데모 진입 버튼과 개발본 안내를 추가했다. 합성 데이터를 운영 기록으로 오해하지 않도록 하기 위함이다.
2. 로그인 폼은 모양과 입력 오류 안내를 유지하지만 실제 인증을 하지 않고 개발본 안내를 표시한다. PIN은 영속 저장하지 않는다.
3. 데모 세션은 버전/만료 시각만 localStorage에 저장한다. 브라우저 저장소를 조작하면 열 수 있으므로 보안 인증으로 사용할 수 없다. 제공하는 내용은 공개 가능한 합성 fixture뿐이다.
4. 단어·지문 탭은 원래 운영 주소로 연결하지 않고 로컬의 미이관 안내 화면으로 이동한다. 관리자도 동일하다.
5. 비교 모집단에 본인 점수가 없으면 원본의 `0등` 대신 석차를 `-`로 표시한다. 별도 회귀 테스트로 검증했다.
6. 사용자가 동작 줄이기를 설정한 경우 차트 애니메이션을 끈다.
7. React의 텍스트 렌더링을 사용하므로 학생명·메모·항목명에 포함된 HTML 문자열은 실행되지 않는다.
8. 원본 Chart.js CDN 4.4.0 대신 로컬 npm Chart.js 4.4.8을 사용한다. 테스트의 원본/React 양쪽에는 같은 로컬 Chart.js를 사용한다. 완전히 동일한 원본 CDN 실행 환경의 픽셀 비교는 아니다.

## 운영 연결 차단

- 운영 adapter와 백엔드 rewrite가 없다. 운영 Supabase URL·공개 키도 실행 소스에 넣지 않았다.
- 빌드 HTML CSP: `connect-src 'none'`, `form-action 'none'`, `object-src 'none'`.
- 개발 환경에서만 로컬 Vite WebSocket 두 주소를 허용하며 HTTP API는 허용하지 않는다.
- Google Fonts 스타일·폰트만 외부 요청을 허용한다. 테스트 레이아웃 비교에서는 양쪽 폰트 요청을 차단해 동일한 시스템 글꼴을 사용한다. 실제 Noto Sans KR 다운로드 환경의 모든 픽셀 일치까지 주장하지 않는다.
- `e2e/legacy/score.html`은 원본에서 운영 URL을 제거하고 테스트 전용 경로로 바꾼 비교 자료다. 브라우저 요청 가로채기로만 제공하며 실제 앱 빌드에 포함되지 않는다.
- 실제 학부모/학생 계정, 운영 저장/삭제/SMS를 테스트하지 않는다.

## 데이터와 테스트

`src/data/demo-score.json`과 `e2e/fixtures/score-response.json`은 동일한 합성 데이터이다. ‘데모 학생’, ‘테스트 고1반’ 및 성적·일정은 실측 기록이 아니다.

검증 과제:

- 순수 계산: 항목 누락/null/0, JSON 우선순위, 동적 항목 중복, 그룹 모집단 fallback, 원점수 누적, 차트 gaps, 날짜 연도 경계, 모의고사 레거시 총점, 석차 미확인.
- React: 재시험 원점수·동적 항목, 빈 데이터·미입력, 세션/데모 로드 오류, 입력 정보 미전송, HTML 텍스트 처리, 직접 지문 경로, reduced-motion.
- 세션: 복원·로그아웃, 만료·손상·저장소 거부, 네트워크 무호출.
- 브라우저: 모바일 390px·PC 1440px에서 원본과 선택 목록·성적 내용·누적 요약 비교. 주간/결석/과제 없음/모의고사/미응시 사례를 선택해 검증.
- 레이아웃: 로그인 입력칸·헤더 및 성적 카드·선택기·요약·차트 크기 비교, 가로 overflow 확인. 주요 요소 너비 허용 오차 2px, 높이 2~3px. 전체 페이지 픽셀 동일성 보장은 아니다.
- 안전성: CSP를 통한 동일 출처 API 및 외부 데이터 fetch 차단, 로컬 경로 유지.

실행 결과는 [검증 기록](VERIFICATION.md)에 보관한다. 테스트가 통과해도 실제 운영 서버의 인증·응답·권한 정책 검증을 대신하지 않는다.

## 후속 구현 시 필수 조건

- 서버 권한과 HttpOnly 세션이 있는 별도 테스트 백엔드를 먼저 확보한다. 현재 demo marker를 실제 로그인 토큰으로 전용하지 않는다.
- 입력 응답은 런타임 스키마로 검증하고 누락/잘못된 타입/세션 만료를 처리한다. 현재 TypeScript 계약은 런타임 데이터 검증기가 아니다.
- 학생·반·시험 ID와 기존 단어 기록을 보존한다. OCR 도입을 위한 콘텐츠 ID 변경은 별도 마이그레이션 과제다.
- 미이관 화면을 정상 동작하는 것처럼 표시하지 않는다.
- 실제 저장·삭제·문자 발송은 승인된 격리 환경과 별도 승인 절차가 갖춰질 때만 연결한다.
